# Arc close — 2026-05-21

Closing the F1.1 / Phase 0.6 / Phase 0.7 cluster. Recording what shipped,
what got deferred, and what the next session picks up.

## What shipped

### F1.1: backward-through-matmul resolved

Commit `472cf86` on `main`, pushed to GitHub.

The micro-bisection from the prior session (`48b7a4d`) pointed at
"backward chain through matmul". This session validated the root cause
with a standalone C POC (`~/tmp/f1_matmul_bw_poc.c`) — three flows side
by side, the middle one reproducing micro5's failure byte-for-byte —
and shipped a one-primitive fix (`tnn_build_forward_only`) that lets
training callers skip the bogus forward sched-alloc.

All five F1.1 micros now PASS:

```
micro1: W 1.0 → 0.98, loss=1, grad=2      (scalar L=W², SGD)
micro2: W 1.0 → 0.92, loss=4, grad=8      (scalar matmul + SGD)
micro3: W'=[0.934, 1.912], grad=[66, 88]  (K=2 matmul + SGD)
micro4: y=11, loss=121                    (forward-only control)
micro5: y=11, loss=121, grad=[66, 88]     (backward-only)
```

Full root cause + fix detail in `docs/design/phase-f1-status.md`.

**What F1.1 did NOT do:** train LoRA adapters on a real model layer.
That's properly F1.2 (SFT loop) and is the next concrete piece.

## What got deferred

### Phase 0.6: graph inlining + legacy deletion → DEFERRED

The original scope doc already explained why: it's a 1-week refactor
not forced by any broken state, with re-divergence risk. This session
made the deferral explicit (`docs/design/phase-06-scope.md` header
flipped to `DEFERRED 2026-05-21`), added concrete re-trigger conditions:

1. Qwen3 MoE landing (~ when CPU/CUDA divergence on FFN-routing forces
   the duplication tax)
2. A CPU/CUDA divergence shipping to production
3. Spinel #626 issue #1 upstream-fix lets us delete `lib/gguf_kv.rb`

Until then: keep the mirror discipline (commit `e7332b8` headers); rely
on the Phase 0.7 gates to catch CPU regressions; rely on the `*_cuda`
smokes for GPU regressions.

## What changed about the rollout

The original Phase F roadmap had F1.0 (smoke), F1.1 (real layer), F1.2
(SFT loop), F2 (CUDA), F3 (full FT), F4 (QLoRA). After this session:

- **F1.0** — minimal LoRA training step. **Done** (prior session).
- **F1.1** — backward-through-matmul correctness. **Done** (this
  session). Renamed in spirit from "LoRA on a real model layer" to
  "in-graph optimizer correctness", since the real-layer training
  work has its own failure modes and warrants its own phase.
- **F1.2** — SFT loop driver + LoRA on a real SmolLM2-135M attention
  projection. **Next.** ~1-2 weeks per `docs/design/finetuning.md`.
- **F2 / F3 / F4** — unchanged. Each one inherits a correct in-graph
  optimizer, so they don't re-bisect the matmul-backward question.

The task list reflects this. F1.2 is the entry point.
