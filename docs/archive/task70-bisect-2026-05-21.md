# Task #70 bisect — narrowing the CPU/CUDA LoRA-train divergence

**Date:** 2026-05-21
**Setup:** SmolLM2-135M, LoRA r=16 on Q, all 30 layers' LoRA params
trainable, LR=0.5, 20 SGD steps. CUDA: CE 7.52→0.21. CPU: CE
7.5194→7.5184. 1000× ratio in convergence rate at identical config.

## Bisect strategy

Forward-construct identical CPU + CUDA smokes that add one suspect op
at a time on top of the toy LoRA training chain (`y = (W+BA)@x`,
`loss = sum(y²)`), which is known CPU == CUDA bit-identical. Compare
loss trajectories digit-for-digit on both backends after 30 SGD steps.

`tinynn/ab_smoke_lora_train{,_cuda}` is the baseline:

```
final loss = 5.7127635955112055e-12 on CPU and CUDA — identical
```

## What's left to explain the divergence

Things that are in the full-SmolLM2 forward but NOT covered by the
bisect smokes (Spinel #626 sub-issue 1 blocks the FFN one specifically):

1. **FFN (SwiGLU) — silu_back and chained matmul backward.**
   `lib/toy_smollm2_ffi_kv.rb` builds: `pre = w_gate @ h2;
   up = w_up @ h2; gate_s = silu(pre); swglu = gate_s * up;
   ffn = w_down @ swglu`. ggml has silu_back; it's bound through
   tinynn already (used elsewhere). The FFN bisect failed to
   compile because Spinel widens Mat#nrows when too many cross-class
   types are in scope (Spinel #626 sub-issue 1 — same upstream bug
   Phase 0.6 re-trigger condition #3 is waiting on).
2. **The cpy backward on KV-cache writes.** Forward writes K/V into
   strided views; backward needs cpy_back through a strided dst.
   We vendored a cpy FORWARD fix (vendor-patches/0004) — the
   backward path may have a similar shape-dependence bug.
3. **Multi-layer composition.** 30 transformer blocks in series.
   For the gradient at layer 0 to differ by 1000× between backends
   over 30 layers, the per-layer divergence factor would need to be
   ~1.25 (since 1.25³⁰ ≈ 800). That's 25 % per layer — far too
   large for a numerical FP32 effect.
4. **Sched intermediate-grad aliasing.** Long backward chain
   produces hundreds of intermediate grad tensors. `set_output` is
   set on the FINAL grad tensors (`grad_A`, `grad_B`) but not on
   the intermediates. CPU's sched may reuse intermediate slots
   more aggressively than CUDA's, leading to stale-read corruption
   in the long chain. **This is the most plausible remaining
   explanation given that single-layer bisects pass.**
5. **The tied embed/unembed gradient.** `logits = mul_mat(token_embed,
   x_final)` uses the embed as both the input table and the unembed
   weight. The backward chain therefore has TWO paths into
   token_embed's gradient (the embed lookup forward + the unembed
   backward). token_embed isn't a param so its grad is discarded,
   but the chain might confuse the sched at scale.

## Recommended next steps when picking #70 up

1. **Force-resolve Spinel #626 #1 enough to compile the FFN bisect.**
   This is the only single-op test we couldn't run. If FFN diverges,
   that's our culprit. If FFN matches, the cause is in (3) or (4).
2. **Test multi-layer composition directly.** Stack 2-block,
   4-block, 8-block versions of the working `concat` smoke and watch
   when the divergence appears.
3. **Add `set_output` on every node in the backward chain** (via a
   tnn primitive that walks `cgraph->grads` after `build_backward`
   and flags each). If that closes the CPU/CUDA gap, sched aliasing
   was the cause and the fix is documented.
4. **Compare bit-by-bit at intermediate tensors in the
   SmolLM2 graph.** Modify `lib/toy_smollm2_ffi_kv.rb#build_attention_qhead_step`
   to optionally `set_output` a chosen intermediate tensor handle.
   Run both backends; download and compare element-wise. Walk inward
   from the loss until divergence appears.

## What we've ruled out

- `ggml_rms_norm_back`: bit-exact vs analytical reference
  (`~/tmp/f1_rms_norm_back_poc.c`).
- `ggml_rope_ext_back`: bit-identical CPU/CUDA at single-layer scale.
- `ggml_soft_max_back`: bit-identical.
- `ggml_scale`'s backward (scalar passthrough): bit-identical.
- `mul_mat` backward through views: bit-identical.
- Vendored `GGML_OP_CONCAT` backward (`vendor-patches/0005`):
  bit-identical at 2-head scale.
- `ggml_add` (residual) backward: bit-identical.
- The F1.1 `tnn_build_forward_only` sched pattern: bit-identical at
  small scale (toy LoRA converges 5.7e-12 on both).
- `tnn_opt_step_sgd`: same param updates produce same downstream
  loss; toy chains converge identically across 60 steps.
